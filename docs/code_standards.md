# 代码规范

适用于新增和修改的 Python、测试、配置及工具契约。架构分工见 [架构规范](architecture_standards.md)，交付流程见 [Git 工作流规范](git_workflow.md)。

## 1. 风格与命名

- 使用 Python 3.11+、UTF-8、4 空格缩进；保留文件现有换行方式，文件末尾保留换行。
- 新模块使用 `from __future__ import annotations`，放在模块文档字符串之后、普通导入之前。
- 模块、函数、变量使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`；内部实现以单下划线标识。
- 导入按标准库、第三方库、项目模块分组，不使用通配符导入。延续目标模块的绝对/相对导入风格，避免循环依赖。
- 函数围绕单一职责组织；复杂条件拆成具有业务含义的判断。避免过深嵌套、魔法值和含糊的布尔参数。
- 中文用户文案、注释和文档字符串可以保留；结构化字段、枚举值和协议键不可为翻译而更名。注释解释原因、约束或兼容性，不复述代码。
- 以可读性和局部一致性为准拆分长行；不为本次改动批量重排无关代码。

## 2. 类型与数据契约

- 公共接口、核心业务函数及新增函数声明参数和返回类型；使用 `list[str]`、`str | None` 等类型语法。
- 优先复用已有 Pydantic 模型、dataclass、枚举和协议。跨层数据不要以重复的匿名字典替代已有契约。
- `Any` 限制在外部未解析数据等必要边界；验证输入后尽早转成明确类型，不让未校验载荷贯穿业务层。
- 可变默认值使用工厂或 `None`，不要把列表、字典作为函数默认参数。
- 外部输入校验覆盖必填、空值、长度、枚举、路径和标识符；类型注解不能替代运行时校验。
- 持久化模型的字段调整必须考虑旧数据加载和版本迁移，不直接删除兼容字段或别名。

## 3. 配置、时间与路径

- 后端环境配置统一放在 `config/settings.py` 的设置类中，沿用 `ONES_`、`GIT_`、`LLM_`、`EMAIL_`、`WECHAT_`、`AGENT_` 等现有前缀。
- CLI/TUI 工作流配置沿用 `src/developer_workflow/config.py` 及现有 setup/store 边界；不要把环境设置与用户工作区配置混成一套全局变量。
- 新配置项必须有类型、默认行为、校验和文档；安全默认值及旧配置兼容性需要回归覆盖。
- 持久化时间使用带时区的 UTC；展示时按用户环境转换。
- 使用 `pathlib.Path` 等路径 API，验证解析后路径位于允许的根目录；不依赖拼接字符串或工作目录假设。
- Windows/macOS 差异放入现有平台适配层；不得通过关闭权限、签名或路径检查来实现跨平台。

## 4. 异步、异常与外部调用

- 异步路径优先使用异步客户端；确需阻塞调用时通过既有执行边界或线程卸载处理，不阻塞事件循环。
- 外部请求和子进程必须有超时、资源清理和输出上限；重试次数有界，仅对明确可恢复的错误重试。
- 写操作重试前确认幂等性，避免重复提交、PR、通知或状态变更。
- 捕获具体异常，转换为领域错误时保留异常链。顶层兜底必须记录真实失败状态，不吞掉异常或伪造成功。
- 区分认证失败、网络故障、数据无效、执行失败与待人工验证；未知原因保持未知。
- 子进程使用参数列表及 `shell=False`，禁止把外部输入拼进 shell 命令；工作流命令复用现有授权和执行器。

## 5. 安全与日志

- 使用现有结构化日志、审计和脱敏设施，通过任务 ID、阶段和错误类别定位问题。
- 不记录密码、令牌、Cookie、私钥、完整认证响应或包含秘密的命令环境；异常信息也要经过脱敏边界。
- 凭据通过已有系统凭据存储读取，不落入配置 JSON、测试快照或仓库。
- ONES 接口调整遵循 [工作流长期约束](developer_workflow_constraints.md)：以授权网页的真实 GraphQL/内部 REST 请求为依据，不猜测接口或工作项类型。
- 不以测试通过为由削弱认证、HMAC、路径边界、只读阶段、快照一致性和审批签名检查。

## 6. 测试与检查

- 测试集中在 `tests/`，文件使用 `test_*.py`，函数名描述条件及预期行为；遵循该目录的 `AGENTS.md`（如有）。
- 行为修复应覆盖触发条件和修复结果；新增门禁还需覆盖拒绝路径、旧任务恢复及重复执行。断言可观察行为，避免只复述实现。
- 外部 HTTP、LLM、Git 发布和通知使用 mock/fake；临时目录、数据库及环境变量相互隔离，不依赖开发者真实凭据。
- 异步测试使用项目现有 pytest-asyncio 配置及 `AsyncMock` 等工具。
- 真实 ONES 测试仅在授权环境显式运行；`ones_lan` 标记用于只读局域网测试，模拟结果不能冒充真实服务或实机验证。
- 不复用仓库内旧的 `pytest-temp` 等 `--basetemp`；优先采用 pytest 默认临时目录，特殊需要使用系统临时目录下的全新路径。

```console
uv run pytest tests/test_ones_gateway.py
uv run pytest
git diff --check
```

先运行受影响模块测试；契约、共享基础设施或跨模块变更运行全套测试。报告实际执行范围、失败、跳过及环境限制。仅文档或其他低影响改动无需添加机械测试。

当前 `pyproject.toml` 未配置 Ruff、Black、mypy 或 pre-commit，不把它们列为已存在的强制门禁。引入工具须单独配置并评估存量代码影响。
