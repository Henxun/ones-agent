# 工作区模块与定时扫描设计

状态：工作区模块已实施。以下定时任务内容为早期建议，第一版实施范围以
[工作区定时任务第一版](workspace_schedules_v1.md) 为准。

## 工作区详情布局

顶部显示工作区、项目、迭代和仓库摘要；仓库列表可折叠，避免占满屏幕。
中间五个 tab：查询缺陷、查询需求、任务看板、关联仓库、定时任务。底部固定返回和删除工作区，
删除保留现有确认框。文本使用中文说明，外部内容只作为普通文字渲染。

- 查询缺陷：进入现有筛选与分析/修复向导，明确项目、迭代范围。
- 查询需求：工作区项目与迭代自动带入；复用现有需求列表和执行向导，不新增 ONES 接口。
- 任务看板：展示本地手动任务和已绑定本工作区仓库映射的自动化任务；手动任务可选择普通任务、缺陷或需求类型，并支持新增、编辑、移动状态和刷新。自动化任务可打开原流程详情。详细约束见 `workspace_task_board_design.md`。
  项目/迭代相同但属于其它工作区的任务不得混入；未绑定和损坏记录仍可在全局 Tasks 查看。
- 定时任务：本阶段展示设计与“尚未启用”，不提供会制造虚假成功的保存/运行按钮。

## 定时任务第一版建议

### 配置表单

名称、启用状态、执行周期（每 N 分钟 / 每天指定时间 / 每周指定日）、IANA 时区、
负责人多选、状态多选、每轮最大缺陷数、动作（仅分析 / 分析并修复）。项目固定为本工作区。
迭代默认当前工作区；如需全部迭代扫描，必须先有跨迭代仓库映射，不能只去掉查询条件。
不使用 JSON、任意 shell 命令或要求用户填写 cron 表达式。

创建默认暂停，预览下一次触发时间、扫描条件和执行权限后明确启用。
“立即扫描”先显示候选预览；只读预览不代表同意批量修复。

### 调度与持久化

调度属于 ones-agent 产品，不使用 Codex App 的个人提醒，也不直接复用旧服务端 Scheduler
的执行链。新增独立服务，复用开发工作流 controller/service、FileRunStore 和 RunTaskSupervisor。
配置和执行记录放在用户私有目录，使用原子写、版本校验和进程租约，支持 Windows/macOS。

第一版仅在 TUI 运行时触发；退出、睡眠期间不运行。恢复时最多合并一次错过触发，
不逐次补跑。使用 UTC 保存时间，按所选时区计算；夏令时重复时刻只运行一次，
不存在的时刻顺延到下一个有效时刻。常驻后台服务另行设计，不暗中安装系统服务。

### 扫描、去重与执行

触发 → 校验工作区和配置 → 分页扫描 → 候选快照 → 去重/限额 → 顺序创建工作流 → 记录结果。

去重键包含工作区、缺陷 ID、动作与源记录版本。已有活动任务或等待审批/人工验证任务则跳过；
已完成且源版本未变化不重复创建。手动与定时入口共用原子占位机制，不以“先查再建”规避竞争。
跨轮/跨进程创建 run 之前记录稳定触发 ID，崩溃后先核查既有 run，防止重复修复。

每个工作区最多一个活动扫描批次；共享仓库的写操作串行，不与手动修复抢同一工作区。
新一轮遇到旧轮未完成则记录跳过。默认每轮最多 3 个缺陷，全局执行并发 1；用户可以缩小限额。
所有任务仍在隔离 worktree 内执行，复用既有有界修复、测试、Review 和基线更新规则。

### 暂停与故障

禁用计划只禁止后续触发，不终止已启动任务；取消任务走现有单独确认入口。
连续 3 轮技术失败自动暂停并显示具体类别；无候选不算失败。认证失效、映射丢失、
权限不足明确提示，不无限重试。修改扫描范围/动作需重新确认启用；删除工作区前展示关联计划，
停用计划并保留历史，不能让调度器继续使用失效映射。

### 审批边界

启用自动修复只授权扫描、创建本地任务和修改隔离工作区，不授权提交、推送、创建 PR、
合并、发布或 ONES 状态变更。测试和审查通过后进入既有人工审批；待实机验证可以披露后交接
Draft PR，不再反复阻塞本地 Review。不得伪造验证结果。

### 界面与验收

列表显示名称、状态、范围摘要、下次时间、最近结果；点开详情编辑表单并查看运行历史。
历史包含计划版本、计划/实际触发时间、候选数、去重跳过数、关联任务和脱敏错误。
任务列表新增来源和关联计划，点击计划可回溯。

开发前确认第一版“仅 TUI 运行时调度”。实现分为模型/存储、只读预览、调度和去重、
受限修复接入、表单及历史五步；测试覆盖时间边界、睡眠恢复、并发去重、崩溃恢复、
共享仓库互斥、禁用/删除、批次限额以及不得自动发布。
