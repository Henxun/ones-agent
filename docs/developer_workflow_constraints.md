# Agent 工作流长期约束

本文件记录已确认的产品约束，不是单次修复日志。修改 `src/developer_workflow/` 的门禁、状态流转、审批、发布或 TUI 前必须阅读。实现细节见 [Draft PR 人工验证交接](developer_workflow_pr_verification_handoff.md)。规则变更须明确说明影响并补充回归测试，不能因会话压缩而丢失约定。

## 任务与阶段

- 本项目负责 agent 工作流；工作流里的业务仓库修复、审查和 PR 与当前 ones-agent 项目本身的提交、PR 必须区分。
- 分析和修复应延续同一 Coding Agent 会话；上下文压缩不应导致重新建任务或丢失方案。
- 已有正确实现时，不为满足“必须修改代码”制造空改动；验证结论不得冒充新修复。
- Review 有可执行代码问题时，自动交回修复，之后测试、再审查。设置有界重试与无进展检测，暂停必须给出具体原因。
- 没有代码问题时，不因尚未执行人工/外部验证而循环 Review。已保存的有效审查可用于重新检查审批条件；代码、测试或范围变化必须重新核验。

## 门禁按阶段区分

| 情况 | 默认 Draft PR 前 | 合并 / 发布前 |
| --- | --- | --- |
| 本地必要测试通过、代码审查无待修问题 | 可生成审批包 | 仍须满足其余要求 |
| 无匹配节点、待人工验证、尚未运行的外部验证 | 写入清单并转交 PR，不要求先完成 | 对实际提交/制品完成所需验证 |
| 缺少历史修复前失败记录 | 明确披露缺口，人工审批 Draft PR | 审核人补验或明确评估限制，不得宣称已证明修复有效 |
| 实际测试失败、验证失败/错误、运行未结束 | 阻断，不可改写成“待验证”绕过 | 同样不放行 |
| 冻结文件或代码/测试快照不一致 | 阻断，重新核验 | 同样不放行 |
| 目标分支相对基线变化 | 自动保留旧工作区，在新工作区迁移修复并重新测试、审查；无法安全恢复或达上限才暂停 | 不允许沿用旧审批 |
| Git 连接/认证失败或流程内部异常 | 明确技术故障，不得冒充人工验证门禁 | 修复故障后重试 |

- `publishing.defer_external_verification_to_pr` 默认 `true`；仅显式严格模式 `false` 要求 PR 前完成外部验证，不得悄悄修改用户配置。
- 缺少记录与失败记录不是一回事，不允许删除失败结果来获得 Draft PR 豁免。
- 不移除认证、路径边界、命令安全、快照一致性或审批签名检查来“跑通流程”。
- 缺陷任务默认最多自动更新基线 3 轮（`max_baseline_refreshes`，0 为关闭）。同一任务/Coding Agent 会话继续；旧工作区、旧测试和审查归档。三方合并遗留文本冲突交回修复阶段，冻结复现冲突或补丁无法迁移则暂停。新基线不得复用旧测试、外部通过记录或审批；不执行强推、旧工作区 reset 或自动发布。进程中断留下的迁移目标保留供恢复核查，不覆盖或清理未知目标。
- 上游已经包含修复、迁移后没有生产改动时，只验证当前代码，不为创建 PR 制造空改动。二进制、删除等无法安全处理的冲突需要人工决策。自动恢复只发生在发布意图创建之前；已经开始发布的任务不能被基线更新重写。

## 审批和发布

- 提交、推送新分支、创建 Draft PR/MR 必须经过明确审批；批准不等于允许合并或发布。
- TUI 审批人从当前配置的 ONES 团队成员中明确选择，展示姓名和成员 ID，审批记录使用稳定成员 ID；不自由填写或默认代选。确认时重新核验成员，不把选择成员等同于该成员登录认证或 ONES 状态变更。成员加载失败/为空时提示错误并禁用确认，不能回退到手填绕过。
- 有项目上下文的审批必须先获取项目角色成员 ID，再分批查询成员资料；不能把空 UUID 列表假定为“查询所有成员”。测试需覆盖真实的按 ID 查询语义，分别报告空成员、异常资料和接口失败，不把所有失败归因于账号权限。
- 待验证项、验收标准、源码快照和 PR 清单必须纳入审批绑定；变化后重新审批。
- 多仓库分别绑定自身快照；仅对有改动仓库发布，不制造空提交。未修改仓库仍须保持证据一致。
- 待验证任务只可标为待处理，不得伪造 `passed`、历史失败日志或实机验证。
- PR 交付后进入 `WAITING_PR_VERIFICATION`，不误标 `COMPLETED`，不重复本地 Review。
- Draft 和 pending 状态不替代托管平台的合并/发布保护；工具不得声称已经配置未核验的仓库保护。

## 环境和界面

- 用户明确允许 TUI 使用本机 Git 配置：提交身份、全局/系统配置、credential helper、SSH 配置及 agent。
  TUI 生产入口开启 use_local_git_config；其它入口默认保持隔离模式。不得因此复制或记录密钥、令牌，
  不继承 GIT_CONFIG_COUNT 等环境注入，不自动执行仓库 hooks，不取消人工审批；MR/PR API 仍须平台令牌。

- TUI 开放人工审批后的 commit、push 与 Draft PR/MR 创建，不再使用 MVP 发布禁用开关或占位客户端。
  GitHub/GitLab 的连接与令牌通过发布配置向导验证并安全保存；缺少令牌须在提交代码前提示配置。
  启用发布能力不等于批准任何任务，不授予合并、发布产品或自动变更 ONES 状态的权限。

- 工作区显示名称单独保存在配置的 workspace_names 中，支持中文和空格；内部 key 不参与重命名。
  旧配置缺失名称时回退显示 key。新建界面生成稳定 ID，任务、定时计划和仓库映射始终按 ID 关联。

- TUI 同时维护 Windows/macOS 平台适配；macOS 使用系统账号目录和 Keychain，不调用 Windows 凭据 API，不把秘密落盘。原生 Codex 使用平台签名校验、私有缓存与执行前快照校验，不能以跨平台为由跳过。模拟测试不等同于 macOS 实机验收。

- 验证按实际需求动态选择 macOS、Windows 或其它环境，不固定平台。节点用表单、节点列表和详情管理，不要求手填 JSON。
- Configuration 按模块分 tab；任务 Overview 展示缺陷信息；状态、暂停原因、下一步、按钮必须一致。
- GitHub / GitLab 使用独立 tab 内嵌表单，不从运行信息跳转向导；保存复用校验、凭据存储和运行环境切换，保留其它模块配置。令牌不回显，端点变更必须提供新令牌，保存配置不等于批准发布。
- Coding Agent 使用独立配置 tab 自动检测本机 CLI 并显式选择。旧配置默认使用 Codex；当前执行后端支持 Codex 与 Claude Code，未接入安全执行和结构化输出协议的其它 CLI 只展示、不可选择。切换必须在任务空闲时重建运行时，不得绕过既有 Git 快照、结果模式和发布审批门禁。
- 新任务持久化创建时选用的 Coding Agent 稳定键和显示名，并在任务详情展示；旧任务明确标记为未记录，不得按当前配置倒推。任务记录不保存本机可执行路径或凭据，Agent 版本未知时不猜测。
- Coding Agent 的认证要求按所选 Provider 隔离；选择 Claude Code 不得强制要求 Codex 凭据，也不得把遗留 Codex 令牌注入 Claude 进程。Provider 注册表必须与可选 Agent 目录一致，不完整或多出未授权实现时启动失败。
- ONES 配置 tab 直接展示编辑表单，不再以按钮跳转到另一编辑页。公开字段回填；账号/密码不回显，留空保留已有凭据，更换服务地址须显式提供新凭据。保存复用配置校验、凭据存储及运行环境切换，保留节点、仓库和工作流配置；不能把浏览配置等同于保存。
- 外部验证与代码问题分别展示。列表存在待验证项，不代表它们就是当前阻断原因。
- 无法确定异常原因时明确写“未知/内部检查失败”，不把通用异常改述为“需要人工验证”。
- 隔离模式（未启用本机 Git 配置）不能导致本机已授权凭据完全不可用。Windows 通过固定的 Git Credential Manager、macOS 通过 osxkeychain 接入系统凭据库；显式 GIT_ASKPASS 优先。不继承任意 helper 脚本、全局配置、hooks 或环境注入，仍禁止交互登录，不输出/持久化明文凭据。其它平台的凭据通道需单独实现，不声称已有同等支持。
- 隔离模式的 Windows SSH 默认通道从系统 API 定位当前用户配置目录，仅使用已有普通文件 known_hosts 和标准命名密钥；不读取密钥内容，不继承 ssh config/ProxyCommand，不信任任务传入的 HOME。保持 StrictHostKeyChecking=yes、BatchMode=yes、UpdateHostKeys=no；显式 SSH 配置优先。没有信任记录或可用密钥时仍失败，不关闭校验、不自动接受主机指纹。

## 必须保持的回归覆盖

- 工作区定时任务只负责扫描和触发，必须复用现有“仅分析 / 分析并修复”流程，不另建简化修复链。
- 启用定时修复不是提交/MR 审批；修复后沿用测试、审查、人工审批、提交、推送与 Draft MR 创建。
- 首版仅 TUI 运行时调度；支持表单创建、编辑、暂停/恢复。暂停不取消已启动任务，错过触发不集中补跑。
- 定时任务保留持久化去重与版本检查；不得因重启、重复点击或编辑竞态重复修复。

- 单/多仓库待验证交接、缺失基线交接、显式严格模式。
- 失败测试/验证、冻结文件、快照与目标分支变化不可绕过。
- 旧任务恢复不重复无意义审查，错误提示与按钮不误导。
- 原生 Draft、审批绑定、幂等发布、未修改仓库不发布。
- 验证测试通过不等于真实 PR 已创建或 macOS/GPU 实机已验证，报告必须区分。
